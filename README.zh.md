# no-misread

<img src="assets/demo.svg" alt="終端機輸出：一段沒有禁用字、沒有破折號的文字仍然沒過，因為每一句都落在前一句的兩個字之內" width="760">

[English](README.md)

你打了一段話給 AI，它做出來的東西不是你要的。你回頭看那段話，才發現自己寫得確實可以有兩種解讀。

反過來也一樣。AI 回你四段字，每段都很整齊，你掃過去，重點那句就這樣滑掉了。

這兩件事其實是同一件事。**中間那層話沒有講清楚，往哪個方向都一樣會出事。**

這是一個 skill 加一支 linter，兩邊都管。**你不用選模式**，文字自己會說它要給誰看。

```console
$ python3 nomisread.py --check my-prompt.md
  "direction": "going out to a machine",
  "direction_why": "detected: 26 句裡有 12 句以祈使句開頭"

$ python3 nomisread.py --check the-answer.md
  "direction": "coming back to a person",
  "direction_why": "detected: 65 句裡只有 2 句在下指令"
```

**往外送。** prompt、指令、tool description、錯誤訊息。這些東西是模型在讀，沒有人可以回頭問你到底什麼意思。歧義才是敵人，所以句子平、短、直白反而是對的。

**收回來。** AI 給你的回答、草稿、README、要掛你名字發出去的貼文。機器腔才是敵人，句子得像人講話那樣有長有短。

## 只有三條規則會反過來

| | 往外送 | 收回來 |
|---|---|---|
| 句子長度 | 整齊，25 字以內 | 長短交錯，不然一看就知道是機器寫的 |
| 縮寫 | 少用，模型會把 `won't` 讀錯 | 留著，人講話本來就這樣 |
| `may` `might` `could` | 少用，讀的人問不到你是哪一種 | 留著，你有多確定本身就是資訊 |

其他規則兩邊共用：隱形字元、主動語態、每個動作都要講清楚是誰做的、講具體的東西而不是講一個範疇、不要開場鋪陳、不要收尾總結、不要用那些被寫爛的字。

所以這不叫折衷。**一段文字只有一個任務**，工具自己判斷是哪一個。判錯的時候用 `--type technical` 或 `--type prose` 蓋過去，那是唯一需要你動腦的時候。

## 用眼睛看不出來的兩件事

**隱形字元。** 零寬空格、word joiner、BOM、軟連字號、不斷行空格。這些東西鍵盤打不出來。它們會活過複製貼上，一路上還會把 `grep` 跟 `diff` 弄壞。`--strip` 全部清掉。

**節奏。** 上面那張圖就是。那段文字沒有任何禁用字，沒有破折號，沒有 `delve`，這個類別裡每一份字表都會放它過。

十二、十四、十四、十三、十二。

人不會這樣寫。人是四個字，然後三十一個字，然後九個字，因為一個念頭講完了它就停了。

偵測研究把這個叫 burstiness。已發表的比較顯示，GPT-4o 大約八成五的句子擠在十五到二十八字這個帶裡，人寫的東西則是從四個字散到五十幾個字，沒有中心。兩個指標都低的文字，偵測器九成以上會標記；光把 burstiness 拉上去，就掉到四成左右。

`--check` 給你兩個數字。`stdev_words` 是離散程度，一個特別長的句子就能把它撐高，所以不能只看它。`band_share` 是落在平均值正負兩成五之內的句子比例，那才是研究真正在講的「擠在中間」。**兩個都不合格才算節奏死板**，這樣刻意寫短的段落就不會被誤判。

## 中文也有一套，而且我自己先被抓到

跑 `--check` 的時候如果看到的是中文，它會換成中文那套規則。中文最明顯的破綻不是用字，是**標點寬度**：

```console
$ python3 nomisread.py --check 我的稿.md
  "問題": {"半形標點": 69, "破折號": 7, "三連排比": 3},
  "結論": "中文裡混了半形標點，這是最明顯的一個破綻"
```

<!-- no-misread: off -->
那個 69 是這份 README 的第一版，我自己寫的。用半形逗號寫中文，是機器或是用英文思考的人才會留下的痕跡，因為真正在打中文的人，全形逗號就在手指底下。除了標點，它還抓翻譯腔（「進行⋯⋯的動作」、「被⋯⋯所」、「透過⋯⋯來」）、抓那批被寫爛的詞（「賦能」、「抓手」、「顆粒度」、「值得注意的是」、「綜上所述」），也抓中文的句長節奏，只是改成算字數。
<!-- no-misread: on -->

## 它會校準到你身上

通用門檻是對「一般寫作者」的猜測，而你不是一般寫作者。

```bash
python3 "$SKILL/lint/nomisread.py" --learn 舊文章.md 筆記.md 信件.md
```

餵它**你自己寫的、沒有經過模型的**文字。它會量出你真實的句長分布，記下哪些「被寫爛的字」其實你本來就在用，之後拿你的基準去檢查後面每一份草稿。

那份字表從來就不是在說這些字有錯。**你在自己四千字的文章裡用了六次 `leverage`，那它就是你的字。** 證據是你文章裡的出現頻率，所以這份清單長不出「你隨口講過一次的偏好」。

它拒絕從模型的產出學習，包括它自己剛改寫完的東西。那個迴圈會讓 profile 慢慢學成模型的習慣，卻還宣稱它描述的是你。

profile 預設放在 `~/.no-misread/voice.json`，跟著人走。團隊想要統一語氣，就在 repo 裡放一份 `./profile/voice.json`，那個優先。`$NOMISREAD_PROFILE` 兩個都蓋過。

## 安裝

```bash
npx skills add ryvn-dev/no-misread --skill no-misread --agent claude-code
```

或者直接 clone：

```bash
git clone https://github.com/ryvn-dev/no-misread ~/.claude/skills/no-misread
```

**Plugin**：把這個 repo 加成 marketplace，然後安裝 `no-misread`。
**Projects 或自訂指令**：貼上 `prompts/system-prompt.md`，大約 250 字。
**Output style**：複製 `output-styles/no-misread.md`。
**只要 linter**：`lint/nomisread.py` 單檔、純標準庫、不用安裝任何東西。

## 用法

```bash
SKILL=~/.claude/skills/no-misread     # 你裝在哪就填哪

python3 "$SKILL/lint/nomisread.py" --strip draft.md > clean.md
python3 "$SKILL/lint/nomisread.py" --check clean.md
python3 "$SKILL/lint/nomisread.py" --self-test
```

直接打 `python3 lint/nomisread.py` 只有在 clone 出來的目錄裡才有效。裝成 skill 之後，路徑要從你安裝的位置組出來。

或者直接開口就好：「幫我把這段改得像人寫的」、「把這個 prompt 改到模型不會誤讀」、「清掉浮水印」。

`--check` 有問題就 exit 1，可以直接接進 CI 當關卡。**這個 repo 每次 push 都會把自己的文件丟進自己的 linter，不過就不給過。**

## 這裡先講一個作弊的方法

只要把一個數字設成關卡，大家就會照著那個數字寫。你可以每一段塞一句三個字的短句去過節奏檢查，離散度上去，`band_share` 下來，燈號變綠，而文章比你動手之前更難看。

這件事沒有東西擋得住，一份不肯承認這點的 README 也不誠實。這個量測描述的是機器文字的**症狀**，它不是好文章的定義。把它當成目標而不是訊號，只會長出另一種怪癖。

這個檢查存在的意義，是讓你注意到每一句都一樣長。**至於要怎麼改，那是寫作判斷，那是你的事。**

## 它不做的事

它不會讓空洞的內容變成真的。沒東西講的段落，改完只是變乾淨，然後還是空的。

它不對抗偵測器，也沒打算對抗。它清掉的是生成留下的痕跡，好讓值得讀的文字用自己的條件被讀。**該揭露你用了 AI 的場合，就去揭露。**

它不解析文法。這支 linter 是正規表達式加上你自己讀。零分代表這支工具知道的東西都乾淨，不代表這是人寫的。

不要對原始碼跑 `--strip`。把字串裡的彎引號換成直引號，那個字串就變了。
